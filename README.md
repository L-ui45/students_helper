# 校园机会雷达 · 新生版

把题目给出的 **26 条校园活动与机会信息（编号 01–26）**，做成一个面向在校学生、**重点照顾新生使用体验**的信息台：
一眼看懂「今天/这周该去哪、怎么报名、要不要小心」，并且能自己发布。

- 交付形态：**零依赖静态网页**（无框架、无构建、无网络请求、无 CDN），单机打开即用。
- 评论：详情页可发表评论（评论按钮 + 评论区），**只存本机 localStorage，刷新不丢**，可删除自己的评论；评论数量同步显示在评论按钮上。
- 主题：**深色 / 浅色一键切换（立即生效，无过渡延迟）**（顶栏按钮）。首次打开跟随系统 `prefers-color-scheme`，用户手选后写入 localStorage 并在首屏渲染前生效（避免闪色）。两套主题共用同一套结构与圆角，只替换颜色变量。
- 页面结构：首屏「今天」+ **KPI 速览条**（今天几场 / 48 小时内截止 / 未来 7 天 / 适合新生），宽屏右侧是**粘性速览侧栏**（最近的截止与开场、我的日程、来源分层与风险、快速开始），窄屏自动落回单列。所有按钮统一胶囊圆角，卡片/抽屉/弹窗用同一套圆角与分层阴影。
- 时间基准：**电脑系统时间**（页面右上角实时显示，`- 1 天 / + 1 天` 仅作演示偏移）。题目信息只写了月日（9月18日—10月28日）、没有写年份，因此**日期年份跟随你电脑的年份**——否则换一年打开，26 条会全部显示「已结束」。
- 数据的最高原则：**发布内容逐字照录，缺失字段标「未注明」，推算内容标「推算」**——不猜、不补、不改写。

## 1. 怎么打开

三种方式任选：

1. **双击 `index.html`**（file:// 直接可用；已避免 ES module / fetch，所以不会被浏览器拦住）。
2. 本地静态服务：`node serve.mjs`，然后打开 <http://127.0.0.1:8017/>（截图验证用的就是它）。
3. 任意静态服务器托管根目录。

无需 `npm install`，无需构建。

## 2. 目录结构

```
index.html            入口（语义化骨架 + 数据来源声明）
assets/app.css        移动优先样式（CSS 变量、响应式、打印/降级）
js/data.js            数据层：26 条发布者（raw 逐字照录）+ 解析字段 + 缺失语义
js/logic.js           逻辑层：纯函数（状态机 / 冲突检测 / 检索筛选 / 排序 / 统计 / 自检器）
js/app.js             交互层：首屏建议、四视图、详情抽屉、我的日程、发布、信息质量页
tests/data.test.cjs   数据自检：26 条齐全、编号连续、发布内容的关键词逐条保留、缺失字段未被填充
tests/logic.test.cjs  逻辑测试：9/19 基准下的状态快照、冲突组、筛选计数、排序、边界口径、自检器负向测试
tests/e2e.browser.mjs 浏览器端到端：真实点击/输入/提交，跑通筛选→详情→收藏冲突→日历下钻→发布→删除
tools/capture-shots.mjs 截图工具：用 CDP 设备仿真（真 390px）截取桌面/移动端各视图
shots/                13 张验证截图（每张都附带「无横向溢出」检查结果）
serve.mjs             零依赖静态服务器（预览与截图验证用）
```

运行自检：

```bash
# 1) 纯 Node 自检（无需浏览器）
node tests/data.test.cjs && node tests/logic.test.cjs

# 2) 浏览器端到端（需要 Chrome/Edge，走 CDP，零第三方依赖）
node serve.mjs 8017 &
chrome --headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/cr-cdp about:blank &
node tests/e2e.browser.mjs 9222 http://127.0.0.1:8017

# 3) 重新采集截图
node tools/capture-shots.mjs 9222 http://127.0.0.1:8017 shots
```

浏览器里也能自查：「信息质量」弹窗底部会实时跑一遍 `validate()`。

### 深链参数（可分享/可刷新保持）

- 无查询参数（首次引导已按要求移除）。
- `#q=关键词&src=来源&cat=类别&quick=快捷筛选&win=时间窗&sort=排序&view=视图&hide=1&id=条目号&day=某天&panel=面板`
  例如 `index.html#id=01` 直接打开 01 号详情，`#panel=quality` 直接打开信息质量页，`#view=calendar` 直接进月历。

## 4. 产品从数据里读出来的关键判断（不是编的，都能在发布者里核对）

1. **今晚（9/19）撞车**：02 AI 应用入门公开课 19:00（约 90 分钟）与 18 网络安全兴趣交流小组 19:30 首次交流重叠 → 自动提示二选一。
2. **9/21 三场重叠**：11 科研入门分享会（19:00—20:30）、14 Git 与 GitHub 零基础工作坊（19:00—20:30）、09 号通知里训练营首训（19:30）三场时间打架。
3. **变更通知合并**：09 是 01 的补充（首训改 9/21 19:30、地点改实验楼 A402、已报名无需重复提交、报名截止不变）；20 是 03 的补充（开发名额已满、改招设计与材料、已投递无需重复提交）。
4. **发布者自相矛盾**：06 写「9 月 23 日起每周三」，但 9 月 23 日是周二 → 标为「口径不一致，建议确认」，不做静默修正。
5. **首训早于报名截止**：01 首训 9/21、报名截止 9/24 → 提示「能否中途加入需确认」。
6. **报名／入围／提交是两回事**：14「提交报名表不代表录取」、07「意向登记不等同于最终作品提交」、15 有两个提交节点、19「报名已截止但可候补入场」。
7. **风险信息保留但加标**：24（「零门槛、日结」+ 要求加私人微信）、25（标题技术交流、正文商家优惠与购买链接）→ 打「需谨慎」并给出理由与核实建议，**不删改发布者**。
8. **字段缺失不猜**：12 费用未提供、06 报名时间未注明、16 截止未注明、17 网盘提取信息 9/22 失效、22/23 场地未定、24 未提供主办方、25 无时间地点 —— 全部显式标出并附「该问什么」的话术。
9. **面向人群边界**：13「仅限大二及以上」→ 新生视角直接标「新生暂不符合」；08/14 明确面向大一。
10. **时间基准的由来**：发布者 01 说「9 月 20 日起每周六训练」，说明 9 月 20 日是周六；在 2025 年历下 9/21 周日、9/27 周六、9/22 周一全部自洽，故取 2025 年。页面不读系统时间，避免评审日不同导致「全都结束了」。

## 7. 验证阶段发现并修复的真实缺陷

产品不是一次写对的，下面每一条都是**先由测试/截图/仿真量化定位、再修代码、再回归验证**（可复现）：

1. **快捷筛选「适合新生」静默失效**：界面用的键是 `适合新生`，逻辑层判的是 `新手友好`，两者不匹配导致新生最关键的一键筛选点了没反应（Node 测试用的是逻辑键所以没抓到，浏览器 e2e 抓到）。已统一键名并加回归断言。
2. **按天筛选时时间线泄漏其他日期**：月历点选 9/21 后，时间线把该条目的 10/20 作品节点也画了出来。已让时间线严格只呈现所选日期。
3. **窄屏横向溢出（390px 实测）**：17 号的「链接有效期」徽章把整段长文案塞进 `white-space: nowrap` 徽章，单卡 min-content 被撑到 439px，把卡片网格轨道从 343px 撑到 439px，文档宽度 455px > 视口 390px。已缩短徽章文案、允许徽章换行、并把所有网格轨道改为 `minmax(0, 1fr)`；复测文档宽 375px、无溢出块。
4. **「回放预计上传」被显示成 00:00**：发布内容只给了 9月20日，代码却按 00:00 呈现，等于凭空造时刻。已按「只有日期 → 整天」处理。
5. **截止瞬间的判定**：写「9月20日12:00 截止」，在 12:00 整仍显示「即将截止」。已改为 `<= 0` 即算截止。
6. **同标签页粘贴深链不生效**：纯 fragment 变化是同文档导航，原先只监听 `popstate`，导致在同一标签页里改 hash 不刷新界面。已补 `hashchange`。
7. **截图假象与「假通过」**：`chrome --window-size=390` 在 Windows 上受最小窗口宽度限制（实际布局约 500px 再被裁成 390px），据此判断「移动端被裁」是误判；同时只用 `mobile:true` 仿真时 Chrome 会把布局视口撑宽，「无横向滚动」断言会永远成立。已改为 CDP 真实设备仿真 + 同时测 `mobile:false/true` 两种条件。
8. **标红文案不统一**：同一件「没有提供」的事写了 16 种说法（`原文未注明` / `原文未注明（可能涉及费用，先问清）` / `原文未注明/发布者未确定` / `报名时间未注明，满员即止` / `长期招募，具体截止时间未注明` …），共 150 个标红单元格。已统一为 **`未注明`**：红字只写「未注明」，表格标题写明约定「标红＝未注明：发布内容没有提供」；若该字段其实有另一条规则（满员即止 / 长期招募 / 需预约）或需要提醒（费用），改用**灰色小字**补充，红字统一但不丢信息。同时修掉一处不一致：`报名方式` 原先只对严格等于「原文未注明」的写法标红，「按原文报名（原文未写明报名方式）」这类**漏标**，现按语义判定。回归断言：抽查 12 条共 89 个标红单元格必须全等于「未注明」。

9. **时间基准改成系统时间后暴露的写死年份**：原来日历月份写死 `[[2025, 8], [2025, 9]]`，一旦年份跟随系统时间（本机 2026），日历上就只剩空格子、也标不出「今天」。已改为跟随绑定年份并标出「2026 年 9 月」。同时原文里「每周六」「每周三」这类星期说法，原先是在数据里写死结论（「9月23日在 2025 年历里是周二」），年份一变就成了假话——现改为**运行时按你电脑的年份核对**，对得上/对不上都会在详情里给出结论（回归断言覆盖 2025 与 2026 两种年份）。

12. **深色模式的两个真实坑**：① 主题偏好用 `STORE.write`（`JSON.stringify`）存成 `"dark"`，而首屏预置脚本直接拿字符串比较，导致**用户手选的主题在下次打开时被系统偏好覆盖**——预置脚本改为 `JSON.parse` 后修复，并加了持久化断言；② 截图脚本原先用"点一次切换按钮"来拍深色图，而这台机器的系统偏好本就是深色，于是点一次反而切到浅色（且每张截图 localStorage 为空时会跟随系统）——改为**每张截图显式写入主题偏好后重新加载**，并用平均亮度校验（深色 33.6 / 浅色 243.8）。

11. **截图工具的 URL 拼接 bug（差点误判成产品问题）**：给截图加缓存参数时把 `?s=` 拼到了 `#` 之后，URL 变成 `/#panel=quality?s=06-quality`，于是深链的 panel/id 值带上了尾巴，抽屉与弹窗在截图里"消失"。我先怀疑是新增的 `backdrop-filter` 与 `captureBeyondViewport` 丢图层，两次都被诊断数据推翻（单独打开同一 URL 时 `.dlg=1`，产品本身一直正常）。改为先拆 hash 再拼 query，并把视口类截图改为普通视口捕获、每张截图独立页面，13 张图全部复核通过。

10. **按需求做的四项调整**：① 时间基准由固定「9月19日 12:00」改为**电脑系统时间**（日期年份随系统年份绑定，否则换年打开会全部显示已结束）；② 移除「回到考核日」按钮，改为「回到现在」（±1 天演示偏移的复位）；③ 删除「使用引导」按钮与首次引导浮层；④ 全站文案里涉及「原文」的表述统一改为「发布者」/「发布内容」（原文本身指代文本时用「发布内容」，避免出现「发布者逐字照录」这类病句）。e2e 已加断言：全页不再出现「原文」二字。

## 8. 已知限制

- 题目信息没有写年份，页面按电脑系统时间的年份呈现这些月日；因此**在不同年份打开，星期与「今天」的位置会变**，这是刻意的（否则产品在非 9 月会全部失效）。
- 发布内容里没有任何报名链接/二维码，本产品因此**不提供外链**，只说明报名方式与需要追问的信息。
- 本机发布只存在浏览器 localStorage（隐私与零后端取舍）；换浏览器/清缓存会丢失，可删除。
- 02/09/15 等没有给出结束时间的地方，状态判断用 90 分钟作粗略估计，界面会注明「结束时间未注明」。
